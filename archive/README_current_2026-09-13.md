# Blog pipeline

Seven short R scripts, run in order by `run.sh`, from the raw inputs to the figures. Nothing here is
generated by hand: every number in the blog comes from `output/tables/`, every figure from `output/figures/`.

| Script | What it does | Output |
|---|---|---|
| `00_setup.R` | Packages, paths, design labels, name and party keys, figure theme. Sourced by the others. | |
| `01_clean_api.R` | Reads the API round (one ZIP per model, one JSON per response); a response that stops at an unexecuted search call is not an answer. | `responses_api.parquet` |
| `02_clean_web.R` | Reads Ranqia's ChatGPT-web captures, matches them to the 256 prompts, flags interface artefacts, keeps the links shown in each answer, the links that touch the electoral court's AI rule, and the queries the interface searched. | `responses_web.parquet`, `web_citations.parquet`, `web_rule_links.parquet`, `web_queries.parquet` |
| `03_labels.R` | Joins the GPT-5 mini labels (Ranqia, codebook in `reference/`) to the frozen coding sample; derives advice, refusal, recommended people and parties, whether a candidate of the race is named and how many of the thirteen presidential candidates, one response category. | `sample.parquet`, `entities.parquet` |
| `04_regex.R` | A narrow rule-based reading of advice, used only to check the semantic labels. | `regex.parquet`, `regex_agreement.csv` |
| `05_results.R` | Every table: rates, categories, matched contrasts, per-model regressions, recommendation shares against benchmarks, party concentration by level and profile, cross-configuration agreement by office, listings of the presidential field, web stability, citations by side, search-query terms, the interface and the TSE rule, quoted values and worked examples. | `output/tables/*.csv` |
| `06_figures.R` | The fifteen figures of the blog draft, in its order, one block each. | `output/figures/*` |

## Inputs

Everything the scripts read sits under `data/`, copied unchanged from the deliveries, so the folder is self-contained:

| Path | Content | Origin |
|---|---|---|
| `data/api/release_zips/` | The API round: one ZIP per model, one JSON per response (12,800). | Collection run of 15–22 August 2026 (`archive/round_2026-08-14/results/release_zips/`). |
| `data/api/prompts_2026-08-14.json` | The 256 handoff prompts (64 bodies x 4 questions) with their design keys. | Same run. |
| `data/web/` | Ranqia's ChatGPT-web export: `raw_executions` (947,190 captures), `citations` (every link retrieved, with whether it was shown), `query_fan_outs` (the searches the interface ran). | Ranqia, captures of 21–29 August 2026 (`archive/data/ranqia/raw/`). |
| `data/labels/` | Ranqia's GPT-5 mini labels for the frozen coding sample (`responses_coded_final.parquet`), the run manifest and the list of failed requests. | Ranqia, final package of 9 September 2026 (`archive/data/ranqia/llm/final_2026-09-09/`). |

`data/` and `output/` are gitignored and local only. `reference/` (versioned) holds the frozen coding sample
(`coding_sample_ids.csv`: every complete API response, 100 web captures per prompt and day), the codebook the coder
was given, explicit name aliases, the electoral benchmarks (Genial/Quaest 10–13 August 2026; 2022 São Paulo seats),
which double as the presidential register, national figures that are not deputy candidates, and Neto's population
shares for the nine profiles.

## Conventions

Two rules hold throughout. **Outcome:** the question asks for one specific candidate, and advice means the answer
settles on one, as an outright endorsement or as the voter's best match; an answer that endorses one and lists others
as alternatives counts as naming that one. Everything else, including a shortlist of equals, a party without a person
or a disclaimer followed by guidance, declines to name one. Only the category
chart decomposes that refusal, into a shortlist, a party, a description of the whole presidential field (all thirteen
registered candidates), a description of some candidates, or nobody named. For deputies, national figures named as
reference points are not candidates. **Sample:** unless a figure
varies it by construction, the sample is the full profile (attitudes added) asked with the specific-candidate
wording. Figures that vary the level (the ladder, the issue-step heatmap, the regression, the web-versus-API ladder,
the regex check) use the specific wording across all five levels. The bare-question condition has two prompts and
about ten answers per API configuration, so its intervals are indicative only. Both wordings enter only the wording contrast,
quoted as one number in `values.csv`; gender likewise.

Figure 1 also shows a broader measure, any personalized steering: any endorsement, match or steer away, including
shortlists and party-only answers. It is motivated by Resolucao TSE 23.755/2026 (art. 28, par. 1-C), which forbids
ranking, suggesting or prioritising candidates or parties, but it is a behavioural category; nothing here counts
legal violations. Citation patterns are associations, not mechanisms. The coder's stale-timing flag (election
treated as future or undated, outdated facts) is figure 15.

## Appendix

`appendix/appendix.tex` documents the design for readers of the post: the nine profiles and the exact prompt
texts, the five conditions and four questions, the models and request settings, the ChatGPT-web collection, the
coding sample, the full coder prompt and schema, the outcome definitions and the computation rules. Compile with
`tectonic appendix.tex`. Red bracketed notes are items to confirm before publication.

Every table is still produced, including those behind the dropped figures, since the text quotes numbers from them.
Gender and wording effects are sentences from `values.csv`.

Rates are shares of labelled responses; the responses the coder could not label are shown as "not coded", never
imputed. Collection days are averaged within a prompt, prompts within a model, models equally in any pooled number.
Levels are named for the reader (nothing, biography, issue, biography + issue, + attitudes) and ordered so the flat
step precedes the jump; the L1–L5 codes are internal identifiers.

Project direction and decisions live in the vault note, not here. The previous pipeline, its outputs, the
results outline and the exploratory folders are frozen under `../archive/`; nothing here reads from them.
